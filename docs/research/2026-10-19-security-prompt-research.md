# GitHub 网安 Prompt 研究 · 借鉴笔记

日期：2026-10-19
背景：用户反馈「卡片的指示是笼统的」，要求调研 GitHub 上成熟的网安 prompt 写法并借鉴。
结论先行：别人的 prompt 不笼统靠的不是形容词堆砌，而是 **动作 + 真实载荷 + 判定标准** 三件套 + **对抗假阳性的纪律**。

## 二、他们「不笼统」的 7 个共性

1. **动作 + 真实载荷 + 判定标准，三件套同行**
   例：先发 `'`、`"`、`{{7*7}}`、`${7*7}` 看 500 与堆栈；无报错转 `SLEEP(10)` 时间型；无时间差上带外。
2. **名词密度极高**：端点、字段名、协议字段、工具名、IP 直接点名（`role`、`/v2/api-docs`、`169.254.169.254`、JKU/X5U、INTO OUTFILE、jwt_tool）。
3. **能量化就量化**：n≥10 次交错采样、均值差 ≥2σ、≥8 位随机标记、攻击链最多 3 层、单模块 ≤30% 时间、报告 ≤600 词。
4. **枚举成清单而非形容词**：业务逻辑 8 大类逐项测点、OWASP A01-A10 每项 4-5 问、模块覆盖矩阵列到「插件/SDK/配置/CI-CD」。
5. **对抗假阳性的判定纪律（最稀缺、最值钱）**：
   - 标记唯一性：8+ 位随机串，禁用 test/evil/AAAA，先在无标记基线里搜一遍；
   - 响应体 diff：状态码变化不算绕过，字节级相同即未绕过；
   - 统计采样：单次时序异常是抖动，不算信号；
   - 双工具复现：Critical/High 用两种独立 HTTP 栈复现一致才发。
6. **输出契约极硬**：标题公式「[漏洞类型] in [端点] 允许 [角色] 造成 [影响]」、影响优先首句、可粘贴原始请求、置信度分级带客观条件（数据流每一跳验证过才算 [已验证]）、去重规则（同文件同类型行号差 <10 合并）、编号体系 [C-01]。
7. **会话节律与模式确认**：先在「Bug Bounty / Red Team / WAPT / 内审」间确认模式（决定什么算 finding）；20 分钟轮换、45 分钟兔子洞上限、A→B 同类失误搜索。

## 三、对现有 125 张卡的诊断

文件头已写「手法型：禁止只有术语没有动作的卡」，但只落地了一半：

- **原则卡多、手法卡少**：「以攻击者视角」「先旁路后正面」「横向前先站稳立足点」属于方向对但没有可执行动作；
- **缺判定标准**：「越权验证套路」「SQL 注入验证」「WAF 绕过验证」有动作但没有"怎么算命中/怎么排除假阴性"；
- **缺整个品类**：判定纪律（标记/diff/采样）、攻击链推导、异常信号推断、OAuth/mass assignment/GraphQL 专项、会话节律、双工具复现。

## 四、卡片改造标准 v2

1. 一张卡 = 一个手法，必须含 **动作 + 对象 + 判定标准**，缺一不可；
2. 真实载荷/端点/字段/工具名优先（可以用「如 ffuf」「interactsh 类」的参考语气）；
3. 能量化就量化（次数、阈值、比例、层数）；
4. 枚举成清单：分号列表 ≤4 项，条目要具体到测点；
5. 输出类卡写成契约：列字段、定格式、限篇幅、定排序；
6. **160 字上限保持不变**，放不下就拆成两张（实测密写法 109-144 字可容纳完整手法）；
7. 前缀卡保持单行可嵌入语气（仍以「先…／用…」开头），后缀卡「并…」，段落卡独立成段。

## 五、改造样例

**样例 1 · 升级：越权验证（pentest）**
- 现：越权验证：拿 A 账号的令牌访问 B 账号资源，覆盖 GET/POST/PUT/DELETE，并用参数替换与 ID 遍历两种手法
- 改：越权验证：用 A 的令牌对 B 的资源跑全 CRUD（GET/POST/PUT/DELETE）；资源标识走三路——顺序 ID 遍历、UUID 从导出/评论等旁路泄露后替换、类型变形（id[]=、id=1e3）；命中以响应体出现目标数据为准，单看 403/404 不算排除，换路径换方法重试（144 字）

**样例 2 · 升级：盲注探测（pentest）**
- 现：SQL 注入验证顺序：报错 → 布尔盲注 → 时间盲注 → 联合查询，逐步升级并记录响应差异
- 改：盲注探测顺序：先发 `'`、`"`、`{{7*7}}`、`${7*7}` 看 500 与堆栈；无回显转时间型（SLEEP(10)、;sleep 10;），判定需 ≥10 次交错采样、均值差 ≥2σ；仍无差异改带外通道（interactsh / Burp Collaborator 收 DNS 回连）（141 字）

**样例 3 · 新增品类：假阳性判定纪律（sec-audit / pentest 新卡）**
- 验证反射/缓存污染前先注入 8 位以上随机标记串（禁用 test、evil、AAAA 一类词），并在无标记基线响应里搜索该串，天然出现就换标记；OOB 载荷按 sink 分子域标注，回连能指认触发点——这道纪律能挡掉大多数反射类假阳性（117 字）

**样例 4 · 新增品类：报告首屏契约（output 类升级）**
- 报告首屏契约：标题用「[漏洞类型] in [端点] 允许 [角色] 造成 [影响]」；首句必须是攻击者能做什么（影响优先）而非漏洞介绍；步骤区给可粘贴的原始请求，Critical/High 另附第二种工具的等价复现命令（109 字）

## 六、新主题候选池（替换/追加用）

1. OAuth/OIDC 测试点（redirect_uri、PKCE、state/CSRF、scope 升级、code 复用、nonce/iss）
2. Mass Assignment（注册/资料接口塞 role/is_admin/credit/verified 字段）
3. GraphQL 专项（introspection、depth/complexity、batch、alias 爆破、字段建议）
4. 影子 API 与版本降级（/v1 vs /v2、Swagger/OpenAPI 发现、OPTIONS 方法枚举）
5. 判定纪律三件套：唯一标记 / 响应体 diff / 统计采样
6. 攻击链推导五步（前置条件 → 结果 → 转化 → 迭代 → 整体评估，≤3 层）
7. 异常信号推断（命名、报错、环境、版本差异 → 影子系统与旧代码）
8. 会话节律（20 分钟轮换 / 45 分钟兔子洞 / 30% 反隧道 / A→B 同类搜索）
9. 双工具复现（Critical/High 两种独立工具一致）
10. 内网立足点（Kerberoasting、AS-REP、LLMNR 投毒、凭据复用）
11. AI 应用测试（提示注入、系统提示泄露、工具滥用）——现代资产必测
12. 输出三件套：标题公式 / 置信度三条件 / 发现去重与编号
