# 提示词方块（Prompt Blocks）

本地、离线、中英双语的提示词拼装工具：**基础句 + 点选修饰卡 → 槽位拼装 → 一键复制**。

给 AI 的提示词不再整包手改：点几张「手法型」卡片，拼成一条精准、可操作的指令，复制去喂给任何 AI。

## 启动

- 首次：`npm install`
- 日常开发：`npm run dev`，浏览器打开 http://localhost:5173
- 打包成单文件：`npm run build` → 产物 `dist/index.html` 可直接双击打开（离线可用）
- 跑测试：`npm run test`

## 怎么用（三步）

1. 在中间「拼装区」输入基础句（例：帮我审计这段代码）
2. 在左侧点卡片插入：**前缀卡**落到句子前段，**后缀卡**接句尾，**段落卡**附在最后；悬停卡片可看全文
3. 右下角「复制」，粘贴给任意 AI
4. 顶栏右上角切换界面语言（中文 / English）：首次打开按浏览器语言自动识别，选择会保存在本地；切换后 **UI、卡片内容、拼装与复制结果全部跟随语言**（英文版为内置英译层；术语本来就保留英文原名）

拼装区里每张已插入的卡都可以：停用（⏸）/ 上移（↑）/ 下移（↓）/ 移除（×）；带变量的卡可以就地填值（如「控制篇幅」的篇幅）。
预览栏支持「手动微调」：改过之后不再自动同步，点「⟳ 与拼装同步」可回到自动模式。

## Step 2：自定义卡 · 配方 · 导入导出

### 自定义卡片

- 左栏切到「**我的卡片**」分栏 → 「+ 新建卡片」，或点预置卡右下角的 ⧉ 「复制为自定义」再改
- 表单字段：标题、分类、模式（前缀/后缀/段落）、正文、标签（逗号分隔，最多 4 个）
- **正文里的 `{占位符}` 会自动提取成变量**，可给每个变量填默认值；删掉占位符，该变量随之消失
- 校验：标题 ≤ 64 字符、正文 ≤ 480 字符且必须单行、标签 ≤ 4 个；不合法时「保存」按钮禁用并列出原因
  - 上限按**中英两层里更长的那层**取：英文界面下「复制为自定义」复制的是英文内容，若按中文口径（24 字 / 160 字）会有 2/3 的预置卡当场存不下去
  - 预置卡本身另有更严的写作约束（中文卡 ≤24 字 / ≤160 字），见下方「怎么加卡」
- 自定义卡与预置卡一样可插入拼装区、可用变量、可存进配方

### 配方

- 顶部工具条「配方」区：点「+ 存为配方」把**当前基础句 + 已插入的卡实例 + 变量值**存成一套
- 点配方名即还原（**会覆盖当前拼装区**，执行前弹确认）；✎ 重命名，× 删除（也需确认）
- 配方会记住每张卡**存配方时所在的槽位**，之后即使改了那张卡的模式，还原时仍回到原槽
- 配方里引用的卡若已被删除，还原时该条目会被跳过并提示
- 配方不保存「手动微调」后的文本（还原后回到自动模式）

### 导入导出

- 顶栏「数据」按钮打开数据管理弹窗
- **导出 JSON**：下载 `prompt-blocks-<时间戳>.json`，内容为 `{ schemaVersion, app, exportedAt, cards, recipes, compose }`——只含**用户卡与配方**（预置卡随代码走，不导出），并带上拼装区状态作为完整备份
- **导入 JSON**：选一个本工具导出的 `.json`（文件必须带 `app: "prompt-blocks"` 与 `schemaVersion` 标记，否则一律拒绝，不会误吞别的 JSON）。用户卡与配方**按 id 合并**，已存在的 id 跳过并计数；形状损坏的条目会被丢弃并计数；冒用 `builtin:` 前缀的卡会被拒绝，不会污染预置卡库
- **拼装区**：文件里带合法拼装区才覆盖；文件里没有就保持当前拼装区不变（确认框里的说明与实际行为一致）
- **清空本地数据**：清空用户卡、配方与拼装区（预置卡与功能不受影响），需二次确认

## 数据存在哪

- 浏览器 `localStorage`，键名 `prompt-blocks:v1`（存拼装区状态、用户卡、配方）
- 界面语言偏好单独存 `prompt-blocks:lang`（`zh` / `en`），与数据互不影响
- 写入失败（隐私模式 / 配额满）会弹提示提醒你「可能没保存」，不会假装成功
- 若本地数据损坏，读取时会把原始内容先另存为 `prompt-blocks:v1:corrupt-backup`，再回退到默认数据并提示你（原内容不会丢）
- 旧版本存下的「变量默认值」在读取时会被自动清理一次（清空前后的中文渲染结果相同，只是切到英文界面时不再残留中文）；你自己填的值一律不动
- 换浏览器 / 清缓存会丢；用上面的「导出 JSON」做备份

## 怎么加卡（改代码）

1. 打开 `src/data/preset/` 下的分类文件（如 `secAudit.ts`），按文件头注释的格式追加卡片对象
2. 规则速记：id 用 `builtin:<分类>-<两位序号>`；`title` ≤ 24 字；`text` ≤ 160 字单行（多要点用「；」）；正文里的 `{变量}` 必须登记进 `vars`（变量名以中文或字母开头，`{{7*7}}` 一类载荷不会被误判）；`tags` 2-4 个
3. 到 `src/data/preset/en/` 对应文件补同 id 的英译（`title` / `text` / `tags`；带变量的卡在 `vars` 里给「原变量名 → 英文变量名 + 默认值」映射，正文变量写成英文 token，如 `{language}`）
4. 运行 `npm run test`：中文卡与英译层的唯一性 / 字段 / 变量登记会自动校验（缺英译、字段超长、token 没登记都会失败）

提示：卡片要写「手法型」指令——动作 + 对象 + 判定标准（怎么算命中、怎么排除假阴性），真实载荷/字段/工具名优先，能量化就量化，标准术语保留英文原名（BOLA、TOCTOU、gadget chain 等）。写法标准与调研依据见 `docs/research/2026-10-19-security-prompt-research.md`，术语来源见 `docs/research/2026-10-19-terminology-sources.md`。

## 目录结构

- `src/lib/`：纯函数核心（`compose` 拼装规则、`reducer` 状态、`storage` 存储与导入导出、`recipe` 配方互转、`cardUtils` 工具），全部有单测
- `src/data/preset/`：预置卡库（150 张，5 类：安全审计 / 渗透测试 / 编程 / 输出格式 / 通用）
- `src/data/preset/en/`：内置英译层（键为卡片 id；`localizeCard` 在 en 界面合并，变量用 `key` 指回原名保证已填值不丢）
- `src/components/`：三栏 UI（卡库 / 拼装区 / 预览）+ 弹窗、卡片编辑器、配方条、我的卡片列表、顶层错误边界
- `docs/superpowers/`：设计文档与实现计划
- `docs/research/`：卡片写法与术语来源调研笔记（GitHub 网安 prompt / 概念库借鉴；术语来源分三轮，见 `2026-10-29-terminology-round3.md`）

## 注意事项

- 断网可用，运行时不发任何外部请求；前端零后端，数据只存在你的浏览器里
- 拼接规则：槽内各段用「，」连接（英文界面用「, 」）；基础句以终结标点结尾时后缀直接连接；段落间空行分隔
- 自定义卡没有英译，切换界面语言时它保持你写的原文；用户自建的配方名同理
- **输出语言随界面语言走**：中文页的「中文输出」卡让 AI 用中文答；英文页对应的是「English output」卡，「输出语言与风格」卡的默认语言也是 English（两处默认都可手动改）。英译层里有回归测试盯着，不允许再出现"英文页却要求中文输出"的卡
- 顶层有错误边界：万一界面渲染出错，会显示可读的错误页，带「刷新页面」和「重置本地数据并重试」两个出口——**浏览器里的数据不会因此丢失**
